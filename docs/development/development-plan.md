# 바로발행 개발 계획

## 제품 목표

GPT에서 작성한 3~5개 글 묶음을 브라우저 안에서 글별로 분리하고, 네이버 블로그에 붙여넣기 좋은 문단·목록·표 형식으로 정리한 뒤 각 글을 따로 복사할 수 있게 한다.

네이버는 외부 HTML 서식의 완전한 보존을 보장하지 않으므로 두 가지 복사 방식을 제공한다.

- **안전 복사:** 정돈된 일반 텍스트를 복사한다.
- **서식 복사(실험):** `text/html`과 `text/plain`을 함께 기록해 제목, 목록, 표, 표 제목행 색상을 최대한 유지한다.

모든 변환은 브라우저 안에서 수행한다. 작성 중 원고는 자동 저장하지 않으며, 사용자가 `글뭉치 저장`을 누른 원고와 비교까지 마친 발행 히스토리, 사용자가 등록한 웹 바로가기는 현재 macOS 사용자 계정의 로컬 DB에 명시적으로 보존한다. 네이버 로그인, 자동 발행, 이미지 업로드, 외부 AI 교정은 MVP 범위에 포함하지 않는다.

## 요구사항

- **REQ-001:** 여러 글을 한 입력창에 붙여넣을 수 있다.
- **REQ-002:** 독립 구분선, `글 N`, `1편`·`2편`, `1번 글`·`2번 글`, `[1번글]`·`[2번 글]` 라벨, 반복되는 Markdown H1 순서로 글을 자동 분리한다.
- **REQ-003:** 분리 근거가 부족하면 원문을 단일 글로 보존하고 경고한다.
- **REQ-004:** H1 또는 첫 번째 유효 문장을 제목으로 추출한다.
- **REQ-005:** 특수 공백, 연속 공백, 줄 끝 공백, 과도한 빈 줄을 정규화한다.
- **REQ-006:** 제목, 강조, 목록, 인용, 링크, 코드, 표 등 핵심 Markdown을 안전한 HTML과 일반 텍스트로 변환한다.
- **REQ-007:** Markdown 표의 첫 행에 배경색·굵기·테두리·열 정렬을 인라인 스타일로 적용한다.
- **REQ-008:** 사용자는 표 제목행 색상을 선택할 수 있다.
- **REQ-009:** 글별 제목, 글자 수, 표 개수, 경고, 미리보기를 확인한다.
- **REQ-010:** 글마다 `안전 복사`와 `서식 복사`를 제공한다.
- **REQ-011:** 리치 클립보드가 불가능하면 일반 텍스트 복사로 자동 대체한다.
- **REQ-012:** 작성 중 입력은 외부로 전송하거나 자동 저장하지 않고, 사용자가 명시적으로 저장한 글뭉치와 비교 완료 발행 히스토리만 사용자 전용 로컬 DB에 저장한다.
- **REQ-013:** 스크립트, 이벤트 속성, 위험한 URL과 임의 HTML을 실행하지 않는다.
- **REQ-014:** 원문은 변환 전까지 보존하고 초기화할 수 있다.
- **REQ-015:** 권장 범위인 3~5개를 벗어나도 처리하되 안내한다.
- **REQ-016:** 모바일과 데스크톱 모두에서 입력, 미리보기, 복사가 가능하다.
- **REQ-017:** 빈 입력과 100,000자 초과 입력을 명확히 차단한다.
- **REQ-018:** 기준 네이버 글의 `이 글에서 볼 내용`, 번호형 질문 소제목, `A:` 핵심 답변, 섹션 구분선을 자동 인식해 같은 시각 계층으로 변환한다.
- **REQ-019:** 표의 기본 제목행은 기준 글과 같은 `#F7F7F7` 회색 배경과 가운데 정렬을 사용하되, 명시적 Markdown 정렬은 보존한다.
- **REQ-020:** `────────────────────`처럼 문자로 그린 긴 구분선은 제거하고 서비스의 표준 구분선 한 개로 교체한다.
- **REQ-021:** 첫 글 앞의 GPT 작업 안내·작성 메모와 복사용 본문에 불필요한 참조형 인용 표시는 제거한다.
- **REQ-022:** 제목 다음 첫 유효 줄이 질문이면 서식 복사 결과에서 기울임꼴로 표시한다.
- **REQ-023:** 글 안의 명시적인 이미지 생성 프롬프트 구역은 본문에서 분리하고 `아래 이미지를 생성해주세요`라는 별도 복사 영역으로 제공한다.
- **REQ-024:** 제목 또는 코드 밖 본문에 `에버랜드`가 명확히 있는 글에만 복사 본문 맨 아래에 우리아이 놀이기구 찾기 안내와 OneCalc 링크를 자동 추가한다.
- **REQ-025:** 글별로 `발행 완료` 상태를 체크할 수 있고 완료된 글에 실제 발행 본문 입력 영역을 제공한다.
- **REQ-026:** 실제 발행 본문과 제공 원고를 브라우저 안에서 비교해 내용 누락·추가, 문단·줄바꿈, 문장 순서, 놀이기구 하단 링크 차이를 알려준다.
- **REQ-027:** 실제 발행본 비교를 완료한 글은 제목, 제공 원고, 실제 발행본, 비교 결과, 완료 시각과 함께 현재 기기의 히스토리에 보존한다.
- **REQ-028:** 발행 히스토리를 최신순으로 확인하고 제공 원고·발행본을 다시 복사하거나 개별 삭제·전체 삭제할 수 있다.
- **REQ-029:** 전문을 입력창에 붙여넣거나 정리 버튼을 누르면 글별 정리를 실행하고 완료 직후 화면 맨 위로 이동한다.
- **REQ-030:** 정리한 원고 묶음을 사용자가 `글뭉치 저장`으로 사용자 전용 로컬 DB에 보존할 수 있다.
- **REQ-031:** 저장한 묶음은 글별 제목·글 수·저장 시각을 최신순으로 보여주고 다시 열 수 있다.
- **REQ-032:** 같은 원문을 다시 저장하면 중복 항목 대신 제목과 최근 저장 시각을 갱신한다.
- **REQ-033:** 저장한 글뭉치는 발행 히스토리와 별도 DB 컬렉션으로 관리하며 개별 삭제·전체 삭제·손상 데이터 복구를 지원한다.
- **REQ-034:** 본문 서식 복사는 글 제목과 불필요한 상단 구분선을 제외하고 첫 질문 기울임과 이후 문단·강조·중간 구분선 서식을 유지한다.
- **REQ-035:** 행 시작 파이프가 `\|`로 이스케이프되거나 정렬행이 `:-:`처럼 짧은 Markdown 표도 실제 표로 복구하고, 뒤 본문을 보존한다.
- **REQ-036:** 번호 라벨로 분리한 글은 묶음 앞 안내문·라벨·별도 제목을 복사 본문에서 제외하고 첫 질문을 16px 기울임꼴로 출력한다.
- **REQ-037:** 번호 라벨이 한 개뿐인 원고도 앞부분이 고신뢰 GPT 복사·분할 안내이고 뒤 구조가 명확하면 해당 라벨을 글 시작점으로 사용하되, 일반 본문 안의 번호 예시는 보존한다.
- **REQ-038:** 네이버 발행본 붙여넣기에서 `text/plain`과 `text/html`을 함께 캡처해 내용과 서식을 별도로 비교한다.
- **REQ-039:** 글자 크기·줄 간격·문단·굵게·기울임·밑줄·목록·표·구분선·링크·정렬·글자색·배경색 차이를 표시한다.
- **REQ-040:** 발행본 입력과 상세 비교는 별도 대화상자에 두고 결과 카드에는 한 줄 상태만 남겨 여러 글의 세로 길이를 줄인다.
- **REQ-041:** 원본 클립보드 HTML은 탭 메모리에서만 사용하고 히스토리에는 제한된 서식 점수와 항목 요약만 저장한다.
- **REQ-042:** 저장한 글뭉치 영역은 기본으로 접고, 사용자가 펼친 경우에도 목록 높이를 제한해 페이지 전체 스크롤을 늘리지 않는다.
- **REQ-043:** Markdown 정렬 구분행 없이 `헤더 | 헤더`와 데이터 행으로 구성된 표도 실제 표로 복구하며, 제목행과 데이터행 사이의 빈 줄 하나는 같은 표로 연결한다.
- **REQ-044:** `A: 핵심 답변` 뒤에 같은 답변의 상세 내용이 이어지면 빈 문단을 별도로 넣지 않고 한 칸 분량의 문단 간격만 적용한다.
- **REQ-045:** 데스크톱에서 원고 입력과 결과 작업 영역의 기본 높이를 맞추고, 긴 원고는 입력 영역 내부 스크롤과 명시적인 접기·펼치기로 관리한다.
- **REQ-046:** `## 에버랜드 1번`, `## 에버랜드 2번`처럼 동일한 주제명과 서로 다른 순번으로 반복되는 Markdown 제목을 글 경계로 인식하며, 주제 묶음 사이에 구분선이 있어도 각 묶음 내부 글을 모두 분리한다.
- **REQ-047:** macOS 바탕화면 바로가기로 앱을 실행하면 런처가 종료된 뒤에도 로컬 개발 서버가 유지되고 브라우저에서 서비스를 열 수 있다.
- **REQ-048:** 주제와 관계없이 모든 글 끝에 지정된 질문·댓글·공감 마무리 문구를 동일하게 자동 추가한다.
- **REQ-049:** 본문에 지정된 질문·댓글·공감 문장이 이미 있으면 코드 밖의 동일 문장을 제거한 뒤 굵은 질문·댓글·공감 순서로 한 번만 표준화한다.
- **REQ-050:** 자동 마무리 문구는 마지막 해시태그와 표준 구분선 뒤에 배치하고 글의 마지막에서 끝나며, 에버랜드 놀이기구 링크와 이미지 생성 프롬프트는 마무리 문구에 섞지 않는다.
- **REQ-051:** `### N번 글 — 제목`과 `### N번 글—제목`처럼 번호 라벨 뒤에 유니코드 대시와 제목이 붙은 형식을 글 경계로 인식하고, 선행 안내문과 라벨·구분 대시는 제거하되 제목 안의 대시는 보존한다.
- **REQ-052:** 사용자가 이름과 공개 HTTPS 웹사이트 URL을 입력해 화면 상단에 새 탭 바로가기를 만들 수 있다.
- **REQ-053:** 웹 바로가기는 최대 6개까지 사용자 전용 로컬 DB에 저장하며 기존 항목의 수정·삭제와 새로고침 복원을 지원한다.
- **REQ-054:** 바로가기 행은 모바일에서도 상단 높이를 과도하게 늘리지 않고 가로 스크롤로 표시하며 다른 로컬 데이터와 별도 저장소를 사용한다.
- **REQ-055:** 일반 `A:`와 `**A: ...**`처럼 굵게 감싼 핵심 답변 뒤에 상세 본문이 이어지면 네이버 붙여넣기에서도 유지되는 빈 줄을 정확히 하나 출력한다.
- **REQ-056:** macOS 바로가기는 다른 개발 앱과 충돌하지 않는 전용 포트를 사용하고 로그인 시 서버를 백그라운드에서 자동 시작한다.
- **REQ-057:** 명시적인 계산 단계는 `1)`·`2)` 번호를 그대로 유지하고 설명·계산식·결과 설명을 모바일에서 읽기 좋은 독립 문단으로 정리하며, 계산식 뒤 설명 앞에는 빈 줄을 정확히 하나 둔다.
- **REQ-058:** 이미 `해시태그 → 구분선 → 고정 마무리`로 정리된 글을 다시 붙여넣어도 구분선을 글 경계로 오인하지 않고 한 편과 마무리 문구 한 세트를 유지한다.
- **REQ-059:** 저장한 글뭉치·발행 히스토리·웹 바로가기를 브라우저 localStorage가 아닌 현재 macOS 사용자 계정의 로컬 D1/SQLite DB에 저장한다.
- **REQ-060:** 로컬 서버·브라우저·컴퓨터를 종료했다 다시 시작해도 저장 데이터가 유지되며 같은 사용자 계정의 다른 브라우저에서도 같은 목록을 읽는다.
- **REQ-061:** 기존 세 localStorage 키의 유효 데이터는 안정적인 마이그레이션 ID로 한 번만 DB에 병합하고, 성공 여부와 관계없이 원본 localStorage는 즉시 삭제하지 않는다.
- **REQ-062:** DB 쓰기는 컬렉션 revision과 원자적 batch를 사용해 다중 탭 충돌과 부분 저장을 막고 기존 건수·문자 합계·중복·정렬 제한을 유지한다.
- **REQ-063:** 로컬 데이터 API는 loopback origin과 JSON 요청만 허용하고 요청 크기·스키마를 검증하며 내부 SQL·경로를 사용자 오류에 노출하지 않는다.
- **REQ-064:** 로컬 데이터 API는 현재 macOS 사용자만 읽을 수 있는 256비트 접근 토큰을 모든 요청에 요구하고 URL query·로그·소스에 토큰을 노출하지 않는다.
- **REQ-065:** 허용 크기 안의 한국어 최대 데이터 세트를 저장할 수 있도록 요청 상한을 12MB로 두고, 초과 스트림은 전체 버퍼링 전에 중단한다.
- **REQ-066:** 여러 서버 인스턴스가 동시에 저장해도 revision 확인과 쓰기를 하나의 D1 원자적 batch에서 처리해 갱신 유실을 막는다.
- **REQ-067:** 개발 실행과 빌드 실행 모두 같은 사용자 전용 DB 경로와 migration 흐름을 사용한다.
- **REQ-068:** 접근 토큰은 서버가 새로 시작될 때마다 교체하고 자식 프로세스 환경에는 전달하지 않으며, 직접 실행은 터미널의 fragment bootstrap 주소를 제공한다.
- **REQ-069:** 직접 실행 전체를 사용자 전용 프로세스 잠금으로 직렬화하고, 이미 전용 포트에서 서버가 실행 중이면 토큰 교체 전에 중단해 현재 브라우저와 서버의 인증 상태를 보존한다.
- **REQ-070:** 오래된 저장 요청의 성공·실패 응답은 더 최신 요청이 시작된 뒤 화면 목록·경고·토스트를 덮지 않고 최신 DB 상태로 수렴한다.
- **REQ-071:** 종료 신호는 잠금 부모가 아니라 실제 서버 자식에 전달하고, 서버 자식이 완전히 종료될 때까지 프로세스 잠금을 유지한다.

## 인수 기준

- **AC-001:** 구분선으로 연결한 3~5개 글은 같은 개수의 결과 카드로 표시된다.
- **AC-002:** 반복 H1 묶음은 각 H1을 제목으로 삼아 분리된다.
- **AC-003:** 모호한 입력은 내용 손실 없이 한 글로 유지되고 경고가 표시된다.

- **AC-063:** 유효한 이름과 ChatGPT·네이버·OneCalc 등 공개 HTTPS 웹사이트 URL을 저장하면 상단 버튼이 즉시 나타나고 새 탭에서 `noopener noreferrer`로 열린다.
- **AC-064:** 등록한 바로가기는 새로고침·서버 재시작 뒤에도 같은 macOS 사용자 계정에서 유지되고, 수정 시 순서와 ID를 유지하며, 개별 삭제는 다른 앱 데이터에 영향을 주지 않는다.
- **AC-065:** 최대 6개 상태에서는 새 항목 추가를 막되 기존 항목 수정·삭제는 가능하다. 빈 이름, 30자 초과 이름, 중복 이름·URL, HTTP·위험 스킴·사용자 정보 포함 URL·localhost·로컬 도메인·IP 주소는 저장하지 않는다.
- **AC-066:** 상단 바로가기 행은 긴 이름을 말줄임하고 모바일에서 한 줄 가로 스크롤을 사용하며 키보드로 링크 열기와 추가·수정·삭제를 수행할 수 있다.
- **AC-067:** `A:` 답변과 상세 본문 사이에는 답변 문단 자체의 하단 여백을 중복 적용하지 않고 빈 `<p><br></p>` 하나만 둔다. 글 끝·다음 질문·목차 앞에서는 불필요한 답변 전용 빈 줄을 추가하지 않는다.
- **AC-068:** 런처와 개발 서버는 단일 포트 설정 파일의 `45173`을 공유하고 리스너 사용자·작업 경로, 정적 상태 파일, 정확한 루트 HTTP 200 응답을 함께 확인해 바로발행 서버를 식별한다. 로그인 LaunchAgent는 브라우저를 열지 않는 백그라운드 모드로 서버를 준비하며, 다른 앱이 사용하는 `5173` 포트는 건드리지 않는다. 자동 실행 런타임은 사용자 전용 0700 디렉터리로 먼저 복사한 동일 파일에서 Apple·OpenAI 서명 체인과 시스템 라이브러리 의존성을 검증한다. 0500 콘텐츠 해시 런타임과 0400 매니페스트를 설치 잠금 안에서 원자적으로 전환해 PATH, 쓰기 가능한 패키지 관리자 상위 경로, 동시 설치와 중간 종료를 신뢰하지 않는다.
- **AC-069:** `1) 설명 → 계산식 → 결과 설명 → 2) 설명` 구조는 HTML과 일반 텍스트에서 같은 순서와 숫자·연산자를 보존한다. 계산 결과에 붙은 `을 공제합니다` 같은 문장은 계산식과 한 칸 띄운 `따라서 ...` 문단으로 분리하되, 일반 번호 목록과 인용문·코드·표 안의 계산식은 변환하지 않는다.
- **AC-070:** 고정 질문 바로 앞의 `---`는 글 분리 경계가 아니라 마무리 구분선으로 인식한다. 기존 마무리 문장과 구분선을 제거한 뒤 해시태그·구분선·질문·댓글·공감 순서로 각각 한 번만 다시 출력한다.
- **AC-071:** 글뭉치·발행 히스토리·웹 바로가기를 저장한 뒤 서버와 브라우저를 모두 종료·재시작해도 동일 데이터가 복원된다.
- **AC-072:** 기존 localStorage 데이터는 정상 항목만 현재 DB 자료와 병합되고 같은 migration ID 재시도는 중복을 만들지 않으며 다른 payload hash는 충돌로 거절된다.
- **AC-073:** 글뭉치 20건·문자 합계 1,000,000자, 히스토리 50건·본문 합계 2,000,000자, 바로가기 6건과 이름·URL 중복 제한이 서버에서도 동일하게 적용된다.
- **AC-074:** 개별 삭제와 전체 삭제는 요청한 컬렉션에만 적용되고 batch 실패나 revision 충돌은 기존 DB 상태를 부분 변경하지 않는다.
- **AC-075:** 작성 중 미저장 입력과 원본 클립보드 HTML은 DB로 보내거나 저장하지 않는다.
- **AC-076:** 데이터 파일은 사용자 전용 `Library/Application Support/바로발행/database` 아래에 저장하고 원격 D1·외부 API로 전송하지 않는다.
- **AC-077:** DB 미준비·네트워크·검증 실패 시 마지막 화면 상태와 기존 localStorage 원본을 보존하고 사용자가 이해할 수 있는 복구 안내를 표시한다.
- **AC-078:** 0400 권한의 접근 토큰이 없는 요청과 위조 요청은 401로 거절되고, 런처는 토큰을 URL fragment로 한 번 전달한 뒤 브라우저 주소에서 즉시 제거한다.
- **AC-079:** 12MB를 넘는 Content-Length 또는 chunked 요청은 서비스·DB 호출 전에 413으로 중단한다.
- **AC-080:** 같은 revision을 읽은 두 repository 인스턴스의 동시 쓰기 중 정확히 하나만 성공하고 다른 하나는 409 충돌로 끝난다.
- **AC-081:** 기존 DB가 한도까지 차 있어도 localStorage 병합이 DB의 기존 행을 밀어내지 않는다.
- **AC-082:** 이전 서버 토큰은 재시작 직후 무효가 되고, 새 토큰은 0400 파일·Worker 전용 env 파일로만 전달되며 migration·Wrangler 프로세스 환경과 로그에 남지 않는다.
- **AC-083:** `npm run dev`와 `npm run start`의 새 브라우저에서도 터미널에 표시된 fragment 주소로 한 번 접속하면 DB 기능을 사용할 수 있다.
- **AC-084:** 실행 중이거나 동시에 시작 중인 서버 위에서 `npm run dev` 또는 `npm run start`를 호출하면 명시적인 중복 실행 오류로 끝나며 기존 접근 토큰은 바뀌지 않는다.
- **AC-085:** 동일 컬렉션의 이전 mutation이 나중에 실패해도 최신 성공 요청이 지운 경고를 다시 표시하지 않는다.
- **AC-086:** `SIGINT`·`SIGTERM` 뒤 실제 서버가 고아 프로세스로 남지 않으며, 서버 종료 전에는 다른 실행이 잠금을 획득하지 못하고 종료 후에는 다시 획득할 수 있다.

## 주요 위험과 대응

- 네이버가 외부 HTML/CSS를 자체 정리할 수 있다. 안전 복사를 기본 경로로 함께 제공하고 서식 복사를 실험 기능으로 명시한다.
- `---`는 본문 구분선일 수 있다. 분리 결과를 반드시 먼저 보여주며 원문을 자동 삭제하지 않는다.
- 한국어 문법 수준의 띄어쓰기는 로컬 규칙만으로 정확히 고칠 수 없다. 중복·특수 공백과 문단만 정리한다.
- 이미지는 복사 대상에 포함하지 않는다. 네이버 포토 업로더로 별도 등록하도록 안내한다.
