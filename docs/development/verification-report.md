## 브라우저 E2E 점검

- 3편 예시 원고를 붙여넣고 구분선 기준으로 3개 결과 카드가 생성되는지 확인했다.
- 표의 오른쪽 정렬과 선택한 제목행 색상이 미리보기에 반영되는지 확인했다.
- 제목을 수정한 뒤 표 색상을 바꿔도 수정한 제목이 유지되는지 확인했다.
- 입력 원문을 다시 수정하면 이전 결과가 즉시 사라져 오래된 글을 잘못 복사하지 않는지 확인했다.
- 모바일 뷰포트에서 본문 가로 넘침이 없고 핵심 복사 버튼 높이가 44px인지 확인했다.
- `format_blog_articles` WebMCP의 정상 입력은 화면 상태를 갱신하고, 빈 입력은 기존 상태를 훼손하지 않은 채 거절하는지 확인했다.
- 제목·안전·서식 복사 버튼의 성공 상태 메시지가 노출되는지 확인했다.
- 공개 기준 글에서 확인한 15px 질문·답변, 16px 목차 제목, 섹션 구분선, `#F7F7F7` 표 제목행과 기본 가운데 정렬이 미리보기 HTML에 반영되는지 확인했다.
- 번호형 H2 앞에 입력된 `---`가 새 글 경계로 잘못 분리되지 않고 중복 구분선 없이 한 편의 글로 유지되는지 확인했다.
- `────────────────────` 같은 문자 구분선과 연속된 Markdown 구분선이 표준 구분선 하나로 정리되고, 질문 소제목 앞에서는 한 번만 출력되며 문장·코드 안의 선 문자는 보존되는지 확인했다.
- 첫 글 앞의 복붙·분할 안내와 번호형 작성 메모, 참조형 인용은 제거되고 실제 미공개 정보 문장·일반 링크·코드 안 참조 문법은 보존되는지 확인했다.
- 제목 뒤 첫 질문 줄만 기울임꼴로 출력되고, 첫 평서문이나 뒤쪽 질문에는 적용되지 않는지 확인했다.
- 이미지 생성 프롬프트가 본문에서 빠져 별도 복사 영역에 표시되고, 다음 본문·코드 예시·일반 이미지 관련 문장이 보존되는지 확인했다.
- 놀이기구 글은 지정 안내와 OneCalc 링크로 끝나고, 일반 글·코드 안 키워드에는 추가되지 않으며 제목 편집 후에도 즉시 재계산되는지 확인했다.
- 글별 `발행 완료` 체크 후 실제 발행 본문 입력 영역과 비교 버튼이 해당 카드에만 표시되는지 확인했다.
- 실제 발행 본문의 누락·추가 문장과 문단 수 차이, 일치도가 비교 결과에 표시되는지 브라우저에서 확인했다.
- 실제 발행 본문을 수정하면 이전 비교 결과가 즉시 무효화되고, 새 원고를 정리하거나 초기화하면 모든 발행 상태가 제거되는지 확인했다.
- 비교 완료 시 발행 히스토리가 즉시 1건 생성되고 제목·완료 시각·비교 상태·일치도가 표시되는지 확인했다.
- 히스토리 상세에서 제공 원고와 실제 발행본, 비교 문제 목록, 두 복사 버튼과 개별 삭제 버튼이 표시되는지 확인했다.
- 페이지를 다시 불러온 뒤 작성 화면은 초기화되지만 저장된 발행 히스토리 1건은 복원되는지 확인했다.

## 보안·데이터 점검

- 입력 HTML, 스크립트, 이벤트 속성, 위험 URL이 실행 가능한 마크업이 되지 않는지 테스트했다.
- 앱 소스에서 외부 원고 전송, D1/R2 사용, 하드코딩된 비밀값이 없으며 비교 완료 히스토리만 브라우저 로컬 저장소에 기록됨을 확인했다.
- React, React DOM, React Server Components 런타임을 19.2.8로 맞췄다.
- 100,000자, 6,000줄, 50편 상한을 적용했다. 48,000줄 공격성 입력은 42ms 안에 `TOO_MANY_LINES`로 거절됐다.
- 허용 한계에 가까운 구분선 5,999줄 입력은 다음 콘텐츠 위치를 한 번만 계산해 로컬 Node 기준 30ms 이내에 처리됐다.
- 90,000자 공백·괄호 및 반복 편집 문구 입력도 선형 처리되며 로컬 Node 기준 5ms 이내에 정리 또는 거절됐다.
- 99,960자의 불완전한 Markdown 링크 반복 입력은 공통 단일 패스 스캐너로 처리되며 로컬 Node 기준 25ms 이내에 렌더링됐다.
- Clipboard API와 `writeText` 권한 거절 모두 레거시 텍스트 복사로 대체되는지 테스트했다.
- 발행본 비교 입력은 100,000자로 제한하고, 악성 HTML처럼 보이는 문자열도 실행하지 않은 채 텍스트 샘플로만 반환하는지 테스트했다.
- 발행본 비교 모듈은 라인 100%, 분기 86.42%, 함수 100% 커버리지를 달성했다.
- 발행 히스토리는 저장·복원·정렬·동일 ID 갱신·삭제·손상 데이터·저장소 예외·용량 제한·직렬화 크기 제한·악성 문자열 보존을 자동 테스트했다.
- 같은 제공 원고의 안정적인 히스토리 ID, 잠금 대기 중 오래된 비교 취소, 저장 실패와 취소의 구분, 용량 경계에서 최근 갱신 기록 보존을 자동 테스트했다.
- 저장·삭제 직전 최신 로컬 데이터를 Web Locks 안에서 다시 읽으며, 코드 재검토에서 CRITICAL/HIGH/MEDIUM 배포 차단 문제가 없음을 확인했다.

## 남은 수동 점검

- 실제 네이버 SmartEditor 로그인 계정에서의 붙여넣기는 수행하지 않았다.
- 네이버 공식 안내상 외부 HTML 복붙의 서식 보존은 보장되지 않는다. Chrome·Whale에서 표 색상, 테두리, 줄간격이 어떻게 정리되는지 발행 없이 최종 확인해야 한다.
- 이미지는 네이버 포토 업로더로 별도 등록해야 한다.

## 결론

로컬 기능, 자동 검증, 브라우저 핵심 흐름은 배포 가능 상태다. 실제 네이버 편집기 호환성은 제품 화면에 안내한 대로 실험적이며, 안전 복사를 항상 대체 경로로 제공한다.
