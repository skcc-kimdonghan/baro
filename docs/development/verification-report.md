- 이미지 생성 프롬프트와 `### 썸네일 생성 프롬프트`가 본문에서 빠져 `아래 이미지를 생성해주세요` 별도 복사 영역에 표시되고, 다음 본문·코드 예시·일반 이미지 관련 문장이 보존되는지 확인했다.
- 제목 또는 코드 밖 본문에 `에버랜드`가 있는 글만 지정 안내와 OneCalc 링크로 끝나고, 일반 놀이기구 글·펜스 및 인라인 코드·이미지 프롬프트에만 단어가 있는 글에는 추가되지 않으며 제목 편집 후에도 즉시 재계산되는지 확인했다.
- 글별 `발행 완료` 체크 후 실제 발행 본문 입력 영역과 비교 버튼이 해당 카드에만 표시되는지 확인했다.
- 실제 발행 본문의 누락·추가 문장과 문단 수 차이, 일치도가 비교 결과에 표시되는지 브라우저에서 확인했다.
- 실제 발행 본문을 수정하면 이전 비교 결과가 즉시 무효화되고, 새 원고를 정리하거나 초기화하면 모든 발행 상태가 제거되는지 확인했다.
- 비교 완료 시 발행 히스토리가 즉시 1건 생성되고 제목·완료 시각·비교 상태·일치도가 표시되는지 확인했다.
- 히스토리 상세에서 제공 원고와 실제 발행본, 비교 문제 목록, 두 복사 버튼과 개별 삭제 버튼이 표시되는지 확인했다.
- 페이지를 다시 불러온 뒤 작성 화면은 초기화되지만 저장된 발행 히스토리 1건은 복원되는지 확인했다.
- 2편 원고를 `글뭉치 저장`으로 보관하면 묶음 대표 제목·각 글 제목·글 수·글자 수·저장 시각이 목록에 표시되는지 확인했다.
- 페이지를 다시 불러온 뒤 저장 글뭉치가 복원되고 `다시 열기`로 원문과 2개 결과 카드가 다시 생성되는지 확인했다.
- 기준 이미지와 같은 질문형 원고를 정리했을 때 미리보기가 제목과 상단 선 없이 첫 질문부터 시작하고, 첫 질문은 기울임꼴이며 이후 일반 문단·굵은 강조와 중간 섹션 선이 유지되는지 확인했다.
- `\|`로 시작하고 `:-:` 정렬행을 사용한 6행 체험 순서 원고가 2열 표로 복구되며, 표 다음의 `기존 파이널 랩을…` 문장도 별도 본문으로 유지되는지 확인했다.
- GPT 안내문 뒤 `1번 글 → 일반 텍스트 제목 → 첫 질문` 원고를 정리했을 때 안내문·라벨·제목과 불필요한 상단 선은 빠지고 16px 기울임꼴 질문부터 시작되는지 확인했다. 라벨 바로 뒤 질문과 같은 문단의 `평서문 → 질문`도 삭제되지 않는지 자동 테스트했다.
- 번호 라벨이 한 개뿐인 실제 재현 원고에서도 고신뢰 안내문·라벨·제목이 빠지고 요청한 첫 질문부터 본문이 시작되는지 브라우저에서 확인했다. 이미 H1·제목 없는 일반 본문·파일 복사 주제가 시작된 뒤 나오는 단일 `1번 글` 예시는 보존하고, 펜스·다중 백틱·미완성·여러 줄 인라인 코드 속 안내문 문구는 분리 근거로 쓰지 않는지 자동 테스트했다.
- 발행 완료 체크 후 카드 높이는 한 줄 상태 행만 늘어나고, 입력창과 상세 비교는 최대 화면 높이 안에서 스크롤되는 별도 대화상자에 표시되는지 확인했다. 3편 결과의 미리보기는 모두 기본으로 접혀 있었다.
- HTML 형식 붙여넣기에서 `HTML 서식 감지됨`이 표시되고 내용 점수와 서식 점수가 분리되는지 확인했다. 글자 크기·줄 간격·문단·강조·목록·표·구분선·정렬·색상 차이는 요약 4건만 먼저 보여주고 나머지는 접힌 세부 목록에서 확인할 수 있었다.
- 저장한 글뭉치 패널은 기본으로 개수 요약과 `목록 보기` 버튼만 표시되고, 펼친 목록은 최대 28rem 높이 안에서 독립 스크롤되며 개별 묶음 상세는 접힌 상태로 시작하는지 확인했다.
- 데스크톱 기본 상태에서 입력 카드와 결과 작업 영역이 같은 760px 높이를 사용하고, 긴 원문과 결과 목록은 각 영역 안에서만 스크롤되는지 확인했다. `입력창 펼치기/접기`는 `aria-expanded` 상태와 레이블을 함께 바꾸고 원문·결과를 보존하며, 모바일에는 고정 높이를 적용하지 않는지 확인했다.

## 보안·데이터 점검

- 입력 HTML, 스크립트, 이벤트 속성, 위험 URL이 실행 가능한 마크업이 되지 않는지 테스트했다.
- 앱 소스에서 외부 원고 전송·원격 D1/R2 사용·하드코딩된 비밀값이 없으며 명시적으로 저장한 글뭉치·비교 완료 히스토리·상단 바로가기만 사용자 전용 로컬 D1/SQLite DB에 기록됨을 확인했다.
- React, React DOM, React Server Components 런타임을 19.2.8로 맞췄다.
- 100,000자, 6,000줄, 50편 상한을 적용했다. 48,000줄 공격성 입력은 42ms 안에 `TOO_MANY_LINES`로 거절됐다.
- 허용 한계에 가까운 구분선 5,999줄 입력은 다음 콘텐츠 위치를 한 번만 계산해 로컬 Node 기준 30ms 이내에 처리됐다.
- 90,000자 공백·괄호 및 반복 편집 문구 입력도 선형 처리되며 로컬 Node 기준 5ms 이내에 정리 또는 거절됐다.
- 99,960자의 불완전한 Markdown 링크 반복 입력은 공통 단일 패스 스캐너로 처리되며 로컬 Node 기준 25ms 이내에 렌더링됐다.
- Clipboard API와 `writeText` 권한 거절 모두 레거시 텍스트 복사로 대체되는지 테스트했다.
- 발행본 비교 입력은 100,000자로 제한하고, 악성 HTML처럼 보이는 문자열도 실행하지 않은 채 텍스트 샘플로만 반환하는지 테스트했다.
- 발행본 내용 비교 모듈은 라인 100%, 분기 86.92%, 함수 100% 커버리지를 달성했다.
- 클립보드 HTML은 DOM에 삽입하거나 실행하지 않고 최대 500,000자 안에서 태그와 인라인 style 문자열만 분석한다. script·style·noscript 블록은 비교 전에 제외하고 원본 HTML은 localStorage나 DB에 저장하지 않는다.
- `12pt`와 `16px`, `#fff`와 `rgb(255,255,255)`, `strong`과 `b`, `em`과 `i`처럼 시각적으로 같은 표현을 정규화해 과도한 차이 판정을 줄이는지 자동 테스트했다.
- 동일한 굵기·링크 개수라도 다른 문구로 적용 위치가 이동하면 차이로 잡고, 같은 적용 결과가 여러 wrapper로 분할된 경우에는 네이버 재직렬화 차이로 보아 일치 처리하는지 자동 테스트했다.
- 실제 발행본에 제목이 함께 복사되면 텍스트뿐 아니라 HTML의 선두 제목 블록도 제외해 본문 서식만 비교하는지 자동 테스트했다.
- 400,000자 미종료 HTML 주석과 16,000쌍의 불일치 닫는 태그를 제한 시간 안에 선형 처리하고, 500,000자의 과도한 가시 텍스트는 복잡도 상한에서 약 60ms 안에 서식 확인 불가로 중단하며, 100,000자 초과 붙여넣기는 문자열 결합 전에 거절하는지 자동 테스트했다.
- 띄어쓰기만 달라 비공백 내용이 같은 발행본은 서식 적용 위치를 공백 제외 문자 기준으로 정렬해 동일 서식을 거짓 차이로 표시하지 않는지 자동 테스트했다.
- 전체 교체 붙여넣기만 HTML 서식 캡처로 인정하며 부분 붙여넣기와 이후 직접 수정은 캡처 HTML을 폐기해 텍스트 전용 비교로 전환하는지 자동 테스트했다.
- 발행 히스토리는 저장·복원·정렬·동일 ID 갱신·삭제·손상 데이터·저장소 예외·용량 제한·직렬화 크기 제한·악성 문자열 보존을 자동 테스트했다.
- 같은 제공 원고의 안정적인 히스토리 ID, 잠금 대기 중 오래된 비교 취소, 저장 실패와 취소의 구분, 용량 경계에서 최근 갱신 기록 보존을 자동 테스트했다.
- 저장·삭제는 서버 mutation queue와 컬렉션 revision으로 직렬화하며, 409 충돌 시 최신 DB 상태를 다시 읽어 제한 횟수 안에서 재계산하는지 자동 테스트했다. 겹쳐 끝난 이전 조회·성공·실패는 요청 세대로 무시하고 최신 DB 상태를 다시 읽으며, 비교 중 원고가 바뀐 경우 이미 기록한 히스토리만 조건부 보상 삭제한다.
- 글뭉치 저장은 안정적 콘텐츠 ID, 동일 원문 갱신, 최신순 정렬, 불변 업데이트, 개별·전체 삭제, 손상 JSON, 잘못된 스키마, quota 오류, 건수·문자·직렬화 한도와 악성 문자열 보존을 자동 테스트했다.
- 웹 바로가기는 ChatGPT·네이버·OneCalc 등 공개 HTTPS 호스트를 허용하고 HTTP·위험 스킴·상대 URL·사용자 정보·localhost·로컬/예약 도메인·잘못된 DNS 라벨·IP 주소를 차단한다. 연속된 마지막 점을 이용한 로컬 주소 우회도 차단한다. 이름과 정규화 URL은 중복을 막고, 사용자 입력 이름은 HTML로 해석하지 않는 React 텍스트로 렌더링하며, 저장 배열과 항목을 불변 값으로 반환하는지 자동 테스트했다.
- 저장 원고가 같은 macOS 사용자 계정에 삭제 전까지 보존된다는 안내와 공용 계정 주의를 화면에 표시하는지 확인했다.
- 실제 Miniflare D1에서 컬렉션별 교체·revision 증가, 세 컬렉션과 마이그레이션 기록의 단일 batch commit, stale revision 전체 롤백, 손상 JSON 명시 오류를 자동 테스트했다. 별도 repository 두 개가 같은 revision으로 동시에 저장할 때 정확히 하나만 성공하고 다른 하나는 충돌로 끝난다.
- 기존 localStorage의 정상·손상·부분 자료를 검증해 한 번만 병합하고, 실패 재시도에서 같은 migration ID를 재사용하며 원본 브라우저 자료를 보존하는지 자동 테스트했다. DB가 컬렉션 한도까지 찬 경우에도 기존 DB 행은 병합 자료 때문에 제거되지 않는다.
- 로컬 데이터 API가 비-loopback GET, 다른 Origin 쓰기, JSON 이외 Content-Type, 접근 토큰 누락·위조, 초과 본문과 잘못된 스키마를 거절하고 SQL·로컬 파일 경로를 오류 응답에 노출하지 않는지 자동 테스트했다. 12MB 상한은 Content-Length와 chunked 스트림 모두 DB 호출 전에 적용되고, 3.6MB 한국어 payload는 정상 수용한다.
- 직접 실행은 사용자 전용 0600 프로세스 잠금을 서버 수명 전체에 유지한 상태에서 전용 loopback 포트가 비어 있는지 토큰 회전 전에 확인한다. 동시에 실행한 두 프로세스 중 정확히 하나만 잠금을 얻고, 사용 중인 포트에서는 토큰을 바꾸기 전에 중단하며 빈 포트 검사는 소켓을 즉시 반환하는지 자동 테스트했다. `SIGTERM`은 0600 PID handshake로 실제 서버에 전달된다. PID 등록을 1.3초 늦추고 서버 종료를 다시 200ms 늦춰도 timeout 없이 신호가 도달하고 경쟁 실행은 잠금을 얻지 못하며 서버 종료 뒤에만 새 실행이 잠금을 획득한다.
- 실제 `launchctl kill SIGTERM`을 실행해 이전 서버 PID와 잠금 보유자가 함께 종료되고 새 단일 리스너·새 단일 잠금 보유자로 자동 재시작되는지 확인했다. 최종 서버는 세 DB 컬렉션 인증 요청에 200, 무인증 요청에 401을 반환하고 리스너 프로세스 환경에는 접근 토큰이 없다.
- DB 디렉터리는 현재 사용자 소유의 실제 디렉터리만 허용하고 0700으로 보정한다. symlink·다른 사용자 소유 경로는 거절하며, migration 실패 시 기존 데이터를 바꾸지 않고 서버 시작을 중단한다.
- 미래 시각 항목이 20건 있어도 방금 저장한 묶음이 한도 정리에서 남고, 저장 직후 재조회한 목록에서 대상 ID를 확인한 뒤에만 성공으로 처리하는지 자동 테스트했다.
- 잘못된 미래 시스템 시각에서 만든 동일 원문 묶음을 정상 시각에서 다시 저장해도 기존 생성·갱신 시각보다 뒤로 가지 않게 보정되어 제목 변경이 유지되는지 자동 테스트했다.
- 같은 원문에서 제목·표 색상·발행 비교 상태를 수정하면 다시 열기 전 교체 확인이 필요한 것으로 판정하며, 반복 버튼은 묶음 제목을 포함한 접근성 이름을 갖는지 확인했다.
- 본문 서식 복사 페이로드가 제목과 상단 구분선 없이 시작하고 뒤쪽 섹션 선과 일반 텍스트를 보존하는지 자동 테스트했다.
- 이스케이프된 선행 파이프와 짧은 정렬 셀을 표로 복구하고, 표 밖 일반 문장·셀 내부 파이프·코드 블록은 과변환하지 않는지 자동 테스트했다.
- `확인할 항목 | 가입내역에서 볼 내용 | 확인 후 할 일`처럼 정렬 구분행이 없는 3열 연속 행을 표로 복구하고, 1~2행 파이프 문장·외곽 파이프를 포함한 문장형 연속 행·열 수 불일치·코드 블록은 원문대로 보존하는지 자동 테스트했다. 마지막 행만 열 수가 다른 5,998행 후보도 로컬 Node 기준 130ms 이내에 처리됐다.
- 제목행과 데이터행 사이에 빈 줄이 하나 있어도 한 표로 연결하며, 문장형 파이프 행 뒤에 별도 표가 오면 앞 문장은 문단으로 보존하고 뒤 표만 변환하는지 자동 테스트했다.
- 문장형 파이프 행의 마침표가 Markdown 굵게나 링크 안에 있어도 보이는 문장을 기준으로 판정해 뒤 표의 제목행을 잘못 흡수하지 않는지 자동 테스트했다.
- 일반 `A:`와 `**A: 과세대상 연금이 연 500만원이라면 연금소득금액은 90만원입니다.**` 형태 모두 상세 본문이 있을 때 답변 문단에 18px 하단 여백만 적용하고 빈 `<p><br></p>`를 생성하지 않는지 화면·복사 결과를 자동 테스트했다. 일반 텍스트에는 빈 줄 하나만 유지하고 중첩 `<strong>`과 `**` 표식은 남지 않는다.
- `## 1번 글 — 제목` 다음 줄에 같은 제목이 반복되는 입력을 자동 테스트해 카드 제목은 유지하고 본문 중복 제목은 제거되며, 실제 첫 질문이 복사 HTML의 첫 문단에서 16px 기울임꼴로 출력되는지 확인했다.
- 런처가 현재 접근 토큰으로 `/api/local-data?collection=shortcuts`에서 200을 받은 경우에만 서버를 준비 완료로 판단하고, 기존 서버 재사용 전 최신 `.webloc`을 원자 갱신하며 최대 60초까지 기다리는지 자동 테스트했다.
- 오대산 재현문에 예전 질문 변형, 쉼표 해시태그, 이미지 1~4 지시, 완성 마무리와 `개선안` 중복을 함께 넣어도 복사용 본문은 `해시태그 → 구분선 → 질문 → 댓글 → 공감` 한 세트만 남고 이미지 지시는 별도 payload에 한 번씩만 남는지 자동 테스트했다. 캐리비안베이 재현문의 `이미지 2 — 1~4번 설명 뒤`도 네 개 이미지와 함께 분리되며, 단일 캡션, 후속 본문·H3~H6 제목, 펜스 코드와 여러 줄 백틱 코드 안의 번호형 예시는 이미지 지시로 과삭제하지 않는다.
- 이미지 프롬프트가 비어 있는 글도 `아래 이미지를 생성해주세요` 복사 payload를 한 문단으로 만들고, 모든 결과 카드가 이미지 요청 영역을 조건 없이 렌더링하도록 검증했다.
- repository bootstrap과 체크인된 0000·0001·0002 Drizzle migration을 서로 다른 빈 Miniflare D1에 적용해 테이블·인덱스 SQL과 세 컬렉션 초기 revision이 동일한지 확인했다. 광고글 선택값은 DB를 닫았다 다시 열어도 유지되고, 기존 글뭉치는 정보글로 복원된다.

## 남은 수동 점검

- 실제 네이버 SmartEditor 로그인 계정에서의 붙여넣기는 수행하지 않았다.
- 네이버 공식 안내상 외부 HTML 복붙의 서식 보존은 보장되지 않는다. Chrome·Whale에서 표 색상, 테두리, 줄간격이 어떻게 정리되는지 발행 없이 최종 확인해야 한다.
- 이미지는 네이버 포토 업로더로 별도 등록해야 한다.

## 결론

로컬 기능, 자동 검증, 브라우저 핵심 흐름은 배포 가능 상태다. 실제 네이버 편집기 호환성은 제품 화면에 안내한 대로 실험적이며, 안전 복사를 항상 대체 경로로 제공한다.
