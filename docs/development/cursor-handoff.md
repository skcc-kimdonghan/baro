# Cursor 인수인계

## 현재 상태

단일 화면 MVP가 구현되어 있다. 핵심 로직은 `lib/formatter.mjs`, 발행본 비교는 `lib/article-comparison.mjs`, 클립보드 계층은 `lib/clipboard.mjs`, 로컬 DB 서비스는 `lib/local-data-service.mjs`와 `db/local-data-repository.mjs`, 화면은 `app/page.tsx`에 있다.

## 변경 시 지켜야 할 계약

- 작성 중 입력 원고와 원본 클립보드 HTML을 DB나 외부 분석 도구로 보내지 않는다. 사용자가 `글뭉치 저장`을 누른 원고만 loopback API로 사용자 전용 DB에 기록한다.
- 원문 HTML은 실행하지 않는다. `dangerouslySetInnerHTML`에는 포매터가 이스케이프해 생성한 문자열만 전달한다.
- 분리 규칙 우선순위는 `독립 구분선 → 글·편 번호 → 반복 H1 → 단일 글`이다. `1편`, `2편: 제목`, `### 1번 글`, `[1번글]`, `### [2번 글] 제목` 형태를 지원한다.
- 번호 라벨 묶음이 문서 시작점에 있거나 H1 없는 앞부분에 고신뢰 GPT 복사·분할 안내가 있을 때만 첫 라벨 앞 안내문을 본문에서 제외한다. 그 외 선행 내용과 펜스·여러 줄 인라인 코드 속 라벨은 보존한다. 빈 라벨 뒤 `일반 제목 → 첫 질문` 구조에서는 제목을 카드 제목으로만 쓰고 첫 질문부터 16px 기울임꼴로 복사하되, 라벨 바로 뒤 질문은 삭제하지 않는다.
- 번호 라벨이 하나뿐이면 라벨이 첫 줄이거나 앞부분이 고신뢰 GPT 복사·분할 안내이고 뒤 구조가 명확할 때만 라벨부터 글로 인식한다. 이미 H1이나 제목 없는 일반 본문이 시작된 뒤 나오는 단일 번호 라벨 예시는 앞 본문과 함께 보존한다.
- 전문 붙여넣기와 정리 버튼은 정리 완료 후 화면 맨 위로 이동한다. 직접 수정 후에는 상단 `바로 정리` 또는 모바일 하단 고정 버튼을 사용한다.
- 안전 복사는 항상 유지한다. 서식 복사는 네이버 호환을 보장하는 기능으로 표현하지 않는다.
- 본문 서식 복사는 제목과 불필요한 상단 구분선 없이 첫 본문부터 시작한다. 일반 텍스트에도 선 문자를 추가하지 않고, 뒤쪽 섹션의 기존 구분선은 중복 없이 보존한다.
- 표 행 시작·끝의 `\|`는 구조 파이프로 복원하고 `:-:` 같은 짧은 정렬 셀을 허용한다. 셀 내부와 코드 블록의 `\|`는 문자로 보존한다.
- 일반 `A:`와 `**A: ...**` 답변 다음에 상세 본문이 오면 답변 margin과 빈 문단을 함께 쓰지 말고, 복사 가능한 빈 문단 하나만 유지한다. 글 끝·다음 질문·목차 앞에서는 답변 전용 빈 문단을 추가하지 않는다.
- 표 색상 값은 6자리 hex만 허용한다.
- 실제 발행 본문과 비교 결과는 비교 완료 후에만 기기 로컬 DB의 히스토리에 저장하며 외부 네트워크로 보내지 않는다.
- 발행본을 전체 교체로 붙여넣을 때만 클립보드 HTML을 현재 탭 메모리에 보관해 내용과 서식을 나눠 비교한다. 부분 붙여넣기나 직접 편집 후에는 HTML을 폐기하고 서식 미확인으로 표시한다.
- 발행본 입력 변경, 제목 변경, 새 원고 정리 시 오래된 비교 결과를 무효화한다.
- 히스토리는 최대 50건·본문 합계 2,000,000자 제한과 스키마 검증을 유지한다.
- 저장 글뭉치는 발행 히스토리와 별도 DB 컬렉션을 사용하고 최대 20건·사용자 문자열 합계 1,000,000자 제한을 유지한다.
- 웹 바로가기는 로컬 DB에 최대 6개만 저장한다. ChatGPT를 포함한 공개 HTTPS 호스트를 허용하되 사용자 정보 포함 URL, localhost·로컬/예약 도메인·잘못된 DNS 라벨·IP 주소는 차단하고, 링크는 항상 `target="_blank" rel="noopener noreferrer"`를 유지한다.
- DB 상태 경로는 `~/Library/Application Support/바로발행/database`다. `npm run dev`와 `npm run start`는 서버 시작 전에 `drizzle/` migration을 같은 경로에 적용하며 실패 시 기동하지 않는다.
- 모든 로컬 데이터 API 요청은 `~/Library/Application Support/바로발행/access-token`의 0400 접근 토큰을 요구한다. query parameter나 로그에 토큰을 넣지 말고 런처의 fragment bootstrap과 timing-safe header 검증을 유지한다.
- 접근 토큰은 새 서버 시작마다 회전한다. 토큰을 `process.env`나 자식 프로세스 환경에 넣지 말고, dev는 Vite config의 보호 파일 읽기, start는 0400 `worker.env`만 사용한다. 직접 실행 TTY의 `보안 시작 주소`와 런처 `.webloc`은 새 토큰으로 갱신해야 한다.
- `app/api/local-data`와 `app/api/local-data/import`는 loopback host, 동일 Origin 쓰기, JSON Content-Type, 3MB 상한과 스키마 검증 계약을 유지한다. 내부 SQL·파일 경로를 응답에 넣지 않는다.
- `local-data-service`의 mutation queue와 컬렉션 revision을 제거하지 않는다. 409 충돌은 브라우저 DB 클라이언트가 최신 스냅샷을 다시 읽은 뒤 제한 횟수 안에서 재계산한다.
- 같은 `localhost:45173` origin의 기존 localStorage 세 컬렉션은 첫 연결 때 안정적인 migration ID와 hash로 한 번만 병합한다. 성공하거나 실패해도 원본 키를 자동 삭제하지 않으며, 병합 때문에 기존 DB 행을 제거하지 않는다.
- 새 저장본은 용량 정리에서 우선 보존하고 저장 직후 대상 ID가 실제 목록에 남았는지 확인한다. 미래 시각에서 생성된 기존 묶음은 갱신 시각을 단조 보정한다. 같은 원문의 제목·표 색상·발행 비교 상태가 달라진 경우에도 다시 열기 확인을 건너뛰지 않는다.
