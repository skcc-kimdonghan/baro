# 바로발행 구현 보고서

## 구현 결과

- **REQ-001~003:** 글 묶음 입력과 `구분선 → 글·편 번호 → 반복 H1 → 단일 글` 우선순위 분리를 구현했다. `1편`, `2편: 제목`, `3편 제목`도 경계로 처리하고 문장 안의 `1편을`은 제외한다.
- **REQ-004~006:** 제목 추출, 공백·문단 정리, 제목·목록·인용·링크·코드 Markdown 변환을 구현했다.
- **REQ-007~008:** Markdown 표의 정렬 표시를 읽고 표 제목행 색상 프리셋을 인라인 스타일로 직렬화했다.
- **REQ-009~011:** 글별 제목·글자 수·표 개수·미리보기와 제목/안전/서식 복사를 구현했다. 리치 클립보드 실패 시 일반 텍스트로 대체한다.
- **REQ-012~014:** 작성 중 입력과 변환은 네트워크 없이 브라우저 메모리에서 동작하며, 입력 HTML은 실행하지 않고 텍스트로 이스케이프한다.
- **REQ-015~017:** 권장 글 수 안내, 반응형 화면, 빈 입력·100,000자 초과 검증을 구현했다.
- **REQ-018~019:** 기준 네이버 글에서 확인한 목차·질문형 소제목·`A:` 답변·섹션 구분선과 회색 표 제목행을 기본 출력 규칙으로 구현했다.
- **REQ-020:** `─`, `━`, `═` 등으로 만든 긴 문자 구분선을 표준 구분선으로 교체하고, 질문 소제목 앞에서는 중복 출력을 막았다.
- **REQ-021:** 첫 글 앞의 복붙·글 분할 안내와 번호형 작성 메모를 제거하고, `([출처][1])` 및 `[1]: URL` 참조형 인용을 복사 본문에서 제외했다.
- **REQ-022:** 제목 뒤 첫 유효 줄이 질문이면 해당 줄만 기울임꼴로 렌더링했다.
- **REQ-023:** 명시적인 이미지 생성 프롬프트를 글별 메타데이터로 분리하고 `아래 이미지를 생성해주세요` 별도 복사 영역을 제공했다.
- **REQ-024:** 놀이기구 관련 글의 마지막에 에버랜드 우리아이 놀이기구 찾기 안내와 클릭 가능한 OneCalc 링크를 자동 추가했다.
- **REQ-025~026:** 글별 `발행 완료` 체크, 실제 발행 본문 입력, 제공 원고 대비 일치도와 누락·추가·문단·순서·놀이기구 링크 차이 표시를 구현했다.
- **REQ-027~028:** 비교 완료 글을 현재 브라우저의 발행 히스토리에 보존하고, 최신순 상세 확인·두 원고 재복사·개별 삭제·전체 삭제를 구현했다.
- **DEV-007:** `format_blog_articles` WebMCP 도구가 화면과 같은 변환 상태를 사용하도록 연결했다.
- 대량 줄 입력은 6,000줄, 결과는 50편으로 제한하고 분리 경로를 선형 처리해 메인 스레드 정지 위험을 줄였다.
- 제목·HTML·일반 텍스트의 Markdown 링크 해석을 공통 단일 패스 스캐너로 통합해 불완전한 링크 반복 입력의 제곱 시간 증가를 제거했다.
- 불규칙한 표의 초과 셀과 일반 역슬래시, 코드 블록 빈 줄, 비연속 번호 목록을 보존한다.
- React 계열 런타임을 보안 수정 버전 19.2.8로 통일했다.

## 핵심 구현 선택

1. 네이버가 외부 HTML 서식 보존을 보장하지 않으므로 안전 복사와 서식 복사를 분리했다.
2. 원문 HTML을 허용 목록으로 정화하는 대신 처음부터 모두 이스케이프해 실행 가능한 태그가 만들어지지 않게 했다.
3. 분리 근거가 부족한 원고는 임의로 자르지 않고 한 편으로 유지한다.
4. 한국어 문법 교정은 외부 API 없이 정확도를 보장할 수 없어, MVP에서는 중복·특수 공백과 문단 경계만 정리한다.
5. 이미지는 복사하지 않고 네이버 포토 업로더 별도 사용을 안내한다.
6. 기준 글의 실제 렌더링 값에 맞춰 본문·질문·답변은 15px 회색 계열, 목차 제목은 16px 굵게, 표 제목행은 `#F7F7F7`과 가운데 정렬을 기본값으로 사용한다.
7. 질문 소제목 앞의 Markdown 구분선은 새 글 경계로 오인하지 않고 같은 글 안의 섹션 구분으로 처리한다.
8. 문자 구분선은 한 줄 전체가 5자 이상의 선 문자일 때만 정리하며, 연속된 문자·Markdown 구분선은 한 묶음으로 처리해 문장 안의 기호와 코드 블록은 보존한다.
9. 생성 메타 제거는 첫 글 제목 이전의 복합 신호에만 적용하며, 인용 정리는 코드 블록 밖에서만 수행해 실제 본문과 일반 링크를 보존한다.
10. Markdown 링크는 정규식 중첩 탐색 대신 괄호 깊이를 추적하는 단일 패스 스캐너로 처리한다.
11. 이미지 프롬프트는 정확한 H2 제목 또는 독립된 인라인 라벨만 인식해 일반 본문과 코드 예시의 과삭제를 막는다.
12. 놀이기구 판정은 제목과 코드펜스 밖 본문의 `놀이기구`에만 적용하고, 기존 하단 문구는 표준 링크로 한 번만 다시 만든다.
13. 발행본 비교는 제목 한 줄이 함께 복사된 경우를 허용하고, 공백을 접은 콘텐츠 비교와 원래 문단 구조 비교를 분리한다.
14. 비교 결과의 예시 줄은 최대 3개·각 140자로 제한하며, 실제 발행 본문은 React 텍스트 노드로만 표시한다.
15. 발행 히스토리는 비교를 마친 뒤에만 현재 브라우저 저장소에 기록하며 최대 50건·본문 합계 2,000,000자로 제한한다.
16. 저장 데이터는 매번 스키마를 검증하고 손상 항목을 제외하며, 저장소 오류가 나도 현재 원고 정리·비교 흐름은 유지한다.
17. 같은 제목·제공 원고는 안정적인 콘텐츠 ID로 같은 히스토리를 갱신하고, 여러 탭의 저장·삭제는 Web Locks로 직렬화한 뒤 최신 저장값을 다시 읽어 병합한다.
18. 비교 저장이 잠금을 기다리는 동안 원고나 발행본이 바뀌면 입력 revision을 다시 확인해 오래된 비교 결과를 저장하지 않는다.
19. 본문 글자 수뿐 아니라 JSON 직렬화 크기도 제한하고, 한도를 넘으면 오래된 기록부터 제외해 저장 직후 다시 읽을 수 없는 상태를 막는다.
20. 저장 실패와 오래된 비교 취소를 구분해, 브라우저 저장이 막혀도 현재 비교 결과는 화면에 표시한다.
21. 원문 합계와 직렬화 크기 제한 모두 최근 갱신 기록을 우선 보존하고, 화면 표시만 최초 완료 시각 최신순으로 유지한다.
