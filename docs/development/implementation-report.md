# 바로발행 구현 보고서

## 구현 결과

- **REQ-001~003:** 글 묶음 입력과 `구분선 → 글·편 번호 → 반복 H1 → 단일 글` 우선순위 분리를 구현했다. `1편`, `2편: 제목`, `3편 제목`, `### 1번 글`, `[1번글]`, `### [2번 글] 제목`도 경계로 처리하고 문장·Markdown 링크·코드 안의 유사 표기는 제외한다.
- **REQ-004~006:** 제목 추출, 공백·문단 정리, 제목·목록·인용·링크·코드 Markdown 변환을 구현했다.
- **REQ-007~008:** Markdown 표의 정렬 표시를 읽고 표 제목행 색상 프리셋을 인라인 스타일로 직렬화했다.
- **REQ-009~011:** 글별 제목·글자 수·표 개수·미리보기와 제목/안전/서식 복사를 구현했다. 리치 클립보드 실패 시 일반 텍스트로 대체한다.
- **REQ-012~014:** 작성 중 입력과 변환은 브라우저 메모리에서 동작하고, 명시적으로 저장한 글뭉치만 loopback 로컬 API를 통해 사용자 전용 DB에 기록하며, 입력 HTML은 실행하지 않고 텍스트로 이스케이프한다.
- **REQ-015~017:** 권장 글 수 안내, 반응형 화면, 빈 입력·100,000자 초과 검증을 구현했다.
- **REQ-018~019:** 기준 네이버 글에서 확인한 목차·질문형 소제목·`A:` 답변·섹션 구분선과 회색 표 제목행을 기본 출력 규칙으로 구현했다.
- **REQ-020:** `─`, `━`, `═` 등으로 만든 긴 문자 구분선을 표준 구분선으로 교체하고, 질문 소제목 앞에서는 중복 출력을 막았다.
- **REQ-021:** 첫 글 앞의 복붙·글 분할 안내와 번호형 작성 메모를 제거하고, `([출처][1])` 및 `[1]: URL` 참조형 인용을 복사 본문에서 제외했다.
- **REQ-022:** 제목 뒤 첫 유효 줄이 질문이면 해당 줄만 기울임꼴로 렌더링했다.
- **REQ-023:** 명시적인 이미지 생성 프롬프트를 글별 메타데이터로 분리하고 `아래 이미지를 생성해주세요` 별도 복사 영역을 제공했다.
- **REQ-024:** 제목 또는 코드 밖 본문에 `에버랜드`가 명확히 있는 글에만 우리아이 놀이기구 찾기 안내와 클릭 가능한 OneCalc 링크를 자동 추가했다.
- **REQ-025~026:** 글별 `발행 완료` 체크, 실제 발행 본문 입력, 제공 원고 대비 일치도와 누락·추가·문단·순서·놀이기구 링크 차이 표시를 구현했다.
- **REQ-027~028:** 비교 완료 글을 사용자 전용 로컬 DB의 발행 히스토리에 보존하고, 최신순 상세 확인·두 원고 재복사·개별 삭제·전체 삭제를 구현했다.
- **REQ-029:** 전문 붙여넣기 또는 정리 버튼 실행 직후 화면 맨 위로 이동하며, 상단·모바일 고정 버튼으로 재정리할 수 있게 했다.
- **REQ-030~033:** 정리한 원고를 글뭉치 단위로 로컬 DB에 저장하고, 제목 목록·글 수·시각 확인, 동일 원문 갱신, 다시 열기, 개별·전체 삭제를 구현했다.
- **REQ-034:** 제목과 본문 복사를 분리하고, 본문 서식 복사는 제목과 불필요한 상단 구분선 없이 시작하면서 첫 질문 기울임·문단·강조·중간 구분선을 유지하게 했다.
- **REQ-035:** 행 시작의 `\|`를 표 구조 파이프로 복원하고 `:-:` 정렬행도 허용해 깨진 표를 실제 표로 변환하면서 뒤 문장을 유지하게 했다.
- **REQ-036:** 번호 라벨 묶음 앞의 GPT 안내문과 본문 안의 라벨·별도 제목을 제외하고, 복사 본문이 16px 기울임꼴 첫 질문부터 시작하게 했다. 라벨 바로 뒤 질문은 제목으로 과삭제하지 않는다.
- **REQ-037:** 번호 라벨이 하나뿐이어도 앞부분에 고신뢰 GPT 복사·분할 안내가 있고 뒤의 제목·질문 구조가 명확하면 라벨부터 글로 인식한다. H1 글이나 일반 본문 속의 단일 번호 라벨 예시는 원문대로 보존한다.
- **REQ-038~039:** 네이버 발행본 붙여넣기에서 텍스트와 HTML을 함께 캡처하고, 내용 점수와 별도로 글자 크기·줄 간격·문단·굵게·기울임·밑줄·목록·표·구분선·링크·정렬·글자색·배경색을 비교한다.
- **REQ-040:** 카드 안의 긴 입력창과 상세 차이 목록을 대화상자로 이동하고 카드에는 발행 체크·요약 배지·비교 버튼만 남겼다. 결과 미리보기도 기본으로 접어 3~5편 목록의 세로 길이를 줄였다.
- **REQ-041:** 원본 클립보드 HTML은 현재 탭 메모리에서만 사용하고 히스토리에는 서식 상태·점수·제한된 점검 항목만 저장한다.
- **REQ-042:** 저장한 글뭉치 패널은 개수 요약만 보이는 접힌 상태로 시작하고, 펼친 목록은 최대 높이 안에서 따로 스크롤되며 각 묶음의 글 제목 상세도 접힌 상태를 유지한다.
- **REQ-043:** 정렬 구분행이 없는 파이프 행은 3행 이상·동일 열 수·비문장형 제목행 조건을 만족할 때 첫 행을 제목행으로 사용해 실제 표로 복구한다. 제목행 직후의 빈 줄 하나를 같은 표로 연결하고 원본 범위의 끝 인덱스로 이동해 데이터행을 중복 처리하지 않는다. 문장 판정 전 Markdown 강조·링크를 보이는 텍스트로 정규화하며, 후보 구간은 선형 스캔해 대량 불규칙 입력의 반복 탐색을 막는다.
- **REQ-044:** `A:` 핵심 답변은 아래 여백 18px을 가진 문단으로 출력하고 상세 내용 문단을 바로 이어 붙인다. 별도 빈 문단 HTML을 제거해 네이버 붙여넣기에서 두 칸으로 벌어지는 현상을 막고, 일반 텍스트는 빈 줄 하나를 유지한다.
- **REQ-045:** 데스크톱 입력 카드와 결과 작업 영역에 같은 760px 높이를 적용했다. 기본 상태의 긴 원문과 결과 목록은 각 영역 안에서 독립 스크롤되고, `입력창 펼치기/접기`는 원문·결과를 잃지 않은 채 편집 높이만 전환한다. 모바일은 기존 자연 높이를 유지한다.
- **REQ-046:** `## 에버랜드 1번`과 `## 에버랜드 2번`처럼 같은 주제명에 서로 다른 번호가 붙은 Markdown 제목을 번호 라벨 경계로 변환한다. 앞 안내문과 경계 제목은 결과 본문에서 제거하고 뒤 글 제목·본문은 보존한다. 구분선이 에버랜드와 롯데월드 묶음을 먼저 나눠도 각 구간에 구조 분리를 다시 적용해 5편+3편을 8편으로 만든다. 같은 주제가 반복되지 않거나 코드 블록 안에 있는 표기는 기존 소제목·코드로 유지한다.
- **REQ-047:** 바탕화면 앱 런처를 저장소 스크립트로 관리하고, 앱 프로세스에 묶인 `nohup npm run dev` 대신 사용자 GUI 세션의 `launchctl submit` 작업으로 서버를 시작하게 했다. 기존 서버 재사용, 전용 포트 점유 감지, 준비 대기, 실행·서버 로그 안내를 유지한다.
- **REQ-048~050:** 주제와 관계없이 모든 글에 지정된 질문·댓글·공감 마무리를 자동 추가한다. 코드 밖의 동일한 고정 문장을 먼저 제거해 기존 위치·서식과 관계없이 `마지막 해시태그 → 구분선 → 질문(굵게) → 댓글 → 공감` 순서로 한 번만 표준화한다. 에버랜드 링크는 해시태그 앞에 두고 이미지 프롬프트는 별도 복사에만 남긴다.
- **REQ-051:** `### 1번 글 — 제목`처럼 번호 라벨과 제목 사이에 긴 대시가 있는 묶음을 공백 유무와 관계없이 분리한다. 경계용 대시만 제거해 뒤 제목을 보존하고 제목 자체의 추가 대시는 유지한다. 반복 라벨 앞이 실제 H1·본문이면 단일 글로 보존해 선행 콘텐츠 손실을 막는다.
- **REQ-052~054:** 헤더 아래에 최대 6개의 웹 바로가기 행을 추가했다. 이름과 ChatGPT를 포함한 공개 HTTPS URL을 로컬 DB에 저장하고, 새 탭 안전 링크·가로 스크롤·추가/수정/삭제 관리 대화상자·교차 탭 갱신을 제공한다. 위험 스킴과 사용자 정보 포함 URL, localhost·로컬/예약 도메인·잘못된 DNS 라벨·IP 주소, 중복 이름·URL, 6개 초과는 저장 단계에서 차단한다.
- **REQ-055:** 일반 `A:`와 외곽 굵게로 감싼 `**A: ...**` 답변을 같은 구조로 인식한다. 상세 본문이 뒤따르면 답변 문단의 하단 margin을 제거하고 복사 가능한 빈 문단 하나를 넣어 네이버가 인라인 스타일을 정리해도 한 칸 간격이 남게 했다. 글 끝·다음 질문·목차 앞에는 답변 전용 빈 줄을 추가하지 않는다.
- **REQ-056:** `5173`을 사용 중인 다른 Vite 앱을 종료하지 않고 바로발행을 전용 포트 `45173`으로 분리했다. 런처와 프레임워크는 같은 포트 파일을 사용하고, 리스너 UID·작업 경로와 정적 상태 파일·정확한 루트 HTTP 200을 모두 확인한다. Vite가 지원하는 host 옵션과 strict-port를 적용하고 사용자 포트 덮어쓰기를 차단했다. 설치 시 ChatGPT 앱의 Node 24.21.0을 사용자 전용 임시 파일로 먼저 복사하고 그 동일 파일의 Apple·OpenAI 서명 체인과 시스템 라이브러리 의존성을 검증한다. 로컬 네이티브 모듈 로딩에 필요한 정확히 세 가지 권한으로 복사본을 다시 서명하고, 0500 콘텐츠 해시 런타임과 0400 매니페스트를 공용 실행 잠금 안에서 원자적으로 전환한다. 로그인 시 브라우저 없이 서버를 준비하는 `RunAtLoad` LaunchAgent와 백그라운드 런처 모드도 추가했다.
- **REQ-057:** `1)`·`2)`처럼 계산 의도가 명확한 단계 번호는 일반 목록으로 바꾸지 않고 설명 문단으로 유지한다. 한 줄 및 두 줄 계산식을 독립 문단으로 합치고, 결과에 붙은 목적격 설명은 계산식 다음의 `따라서 ...` 문단으로 분리해 빈 줄 하나를 둔다. 입력의 숫자와 연산자는 그대로 보존하며 일반 번호 목록, 인용문, 코드와 표는 기존 렌더링을 유지한다.
- **REQ-058:** 기존 고정 마무리를 제거한 뒤 종단 구분선과 해시태그를 다시 수집해 새 순서로 직렬화한다. 고정 질문 직전의 구분선은 글 경계 판정에서 제외해 완성된 글을 다시 붙여넣어도 두 편으로 갈라지지 않는다.
- **REQ-059~067:** 글뭉치·발행 히스토리·웹 바로가기를 macOS 사용자 전용 D1/SQLite DB에 저장한다. 컬렉션별 revision 확인과 쓰기를 같은 원자적 batch에 넣어 서버 인스턴스 간 경쟁 저장과 부분 저장을 막고, 기존 세 localStorage 컬렉션은 안정적인 마이그레이션 ID로 한 번만 병합한다. API는 loopback host·동일 Origin JSON 요청·현재 사용자 전용 접근 토큰을 요구하고 12MB 스트리밍 상한과 스키마 검증을 적용하며 내부 SQL·파일 경로를 노출하지 않는다.
- **DEV-007:** `format_blog_articles` WebMCP 도구가 화면과 같은 변환 상태를 사용하도록 연결했다.
- 대량 줄 입력은 6,000줄, 결과는 50편으로 제한하고 분리 경로를 선형 처리해 메인 스레드 정지 위험을 줄였다.
- 제목·HTML·일반 텍스트의 Markdown 링크 해석을 공통 단일 패스 스캐너로 통합해 불완전한 링크 반복 입력의 제곱 시간 증가를 제거했다.
- 불규칙한 표의 초과 셀과 일반 역슬래시, 코드 블록 빈 줄, 비연속 번호 목록을 보존한다.
- React 계열 런타임을 보안 수정 버전 19.2.8로 통일했다.

## 핵심 구현 선택

1. 네이버가 외부 HTML 서식 보존을 보장하지 않으므로 안전 복사와 서식 복사를 분리했다.
2. 원문 HTML을 허용 목록으로 정화하는 대신 처음부터 모두 이스케이프해 실행 가능한 태그가 만들어지지 않게 했다.
3. 분리 근거가 부족한 원고는 임의로 자르지 않고 한 편으로 유지한다.
4. 한국어 문법 교정은 외부 API 없이 정확도를 보장할 수 없어, MVP에서는 중복·특수 공백과 문단 경계만 정리한다.
5. 이미지는 복사하지 않고 네이버 포토 업로더 별도 사용을 안내한다.
6. 기준 글의 실제 렌더링 값에 맞춰 일반 본문·번호형 질문·답변은 15px 회색 계열, 글 첫 질문은 16px 기울임꼴, 목차 제목은 16px 굵게, 표 제목행은 `#F7F7F7`과 가운데 정렬을 기본값으로 사용한다.
7. 질문 소제목 앞의 Markdown 구분선은 새 글 경계로 오인하지 않고 같은 글 안의 섹션 구분으로 처리한다.
8. 문자 구분선은 한 줄 전체가 5자 이상의 선 문자일 때만 정리하며, 연속된 문자·Markdown 구분선은 한 묶음으로 처리해 문장 안의 기호와 코드 블록은 보존한다.
9. 생성 메타 제거는 첫 글 제목 이전의 복합 신호에만 적용하며, 인용 정리는 코드 블록 밖에서만 수행해 실제 본문과 일반 링크를 보존한다.
10. Markdown 링크는 정규식 중첩 탐색 대신 괄호 깊이를 추적하는 단일 패스 스캐너로 처리한다.
11. 이미지 프롬프트는 정확한 H2 제목 또는 독립된 인라인 라벨만 인식해 일반 본문과 코드 예시의 과삭제를 막는다.
12. 에버랜드 판정은 제목과 펜스·인라인 코드 밖 본문의 `에버랜드`에만 적용한다. 이미지 프롬프트와 기존 하단 문구는 판정 전에 제거해 일반 놀이기구 글이나 오래된 CTA가 조건을 스스로 충족하지 않으며, 조건을 만족하는 기존 CTA는 표준 링크로 한 번만 다시 만든다.
13. 발행본 비교는 제목 한 줄이 함께 복사된 경우를 허용하고, 공백을 접은 콘텐츠 비교와 원래 문단 구조 비교를 분리한다.
14. 비교 결과의 예시 줄은 최대 3개·각 140자로 제한하며, 실제 발행 본문은 React 텍스트 노드로만 표시한다.
15. 발행 히스토리는 비교를 마친 뒤에만 로컬 DB에 기록하며 최대 50건·본문 합계 2,000,000자로 제한한다.
16. 저장 데이터는 매번 스키마를 검증하고 손상 항목을 제외하며, 저장소 오류가 나도 현재 원고 정리·비교 흐름은 유지한다.
17. 같은 제목·제공 원고는 안정적인 콘텐츠 ID로 같은 히스토리를 갱신하고, 서버의 mutation queue와 DB revision으로 여러 탭의 저장·삭제를 직렬화한다.
18. 비교 저장이 잠금을 기다리는 동안 원고나 발행본이 바뀌면 입력 revision을 다시 확인해 오래된 비교 결과를 저장하지 않는다.
19. 본문 글자 수뿐 아니라 JSON 직렬화 크기도 제한하고, 한도를 넘으면 오래된 기록부터 제외해 저장 직후 다시 읽을 수 없는 상태를 막는다.
20. 저장 실패와 오래된 비교 취소를 구분해, 로컬 DB 저장이 실패해도 현재 비교 결과는 화면에 표시한다.
21. 원문 합계와 직렬화 크기 제한 모두 최근 갱신 기록을 우선 보존하고, 화면 표시만 최초 완료 시각 최신순으로 유지한다.
22. 빈 입력 또는 전체 선택 붙여넣기는 선택 범위를 안전하게 합성한 뒤 길이 검증·정리·결과 포커스 이동을 한 흐름으로 처리한다. 부분 붙여넣기는 연속 편집을 방해하지 않도록 기본 입력 동작을 유지한다.
23. 모바일 고정 버튼에는 safe-area 하단 간격을 적용하고 페이지 본문에도 충분한 하단 여백을 둬 마지막 히스토리 컨트롤을 가리지 않는다.
24. 정리 성공 시 reduced-motion 설정을 존중해 화면과 키보드 초점을 함께 맨 위로 이동하고 완료 상태를 보조기기에 알린다.
25. 저장 글뭉치는 발행 히스토리와 다른 DB 컬렉션을 사용하며 원문·표 색상·제목 목록만 저장한다. HTML은 저장하지 않는다.
26. 원문을 정규화한 안정적 콘텐츠 ID로 같은 묶음의 중복 저장을 막고, 최대 20건·사용자 문자열 1,000,000자·직렬화 1,250,000자로 제한한다.
27. 저장본을 다시 열 때 최신 포매터로 원문을 재정리하고 글 수가 같으면 사용자가 수정해 저장한 제목을 순서대로 복원한다.
28. 저장 원고가 삭제 전까지 같은 macOS 사용자 계정에 남는다는 개인정보 안내를 표시하고, revision 충돌 시 최신 DB 상태를 다시 읽어 재시도한다.
29. 저장 한도 정리에서도 사용자가 방금 저장한 묶음을 우선 보존하고 저장 직후 다시 읽어 대상 ID를 확인한다. 미래 시각에 생성된 기존 묶음도 갱신 시각을 단조 보정해 같은 원문을 계속 수정할 수 있다. 같은 원문이어도 제목·표 색상·발행 비교 상태가 바뀌었다면 다시 열기 전에 확인하며, 반복 동작 버튼에는 묶음 제목을 포함한 접근성 이름을 제공한다.
30. 복사용 HTML과 일반 텍스트 모두 불필요한 상단 선 없이 첫 본문으로 시작하고, 뒤쪽 질문 섹션의 구분선만 그대로 보존한다.
31. 이스케이프 해제는 표 행의 양끝에만 적용해 셀 내부 `\|`와 코드 블록은 문자 그대로 보존하며, 헤더 다음 모든 정렬 셀이 유효할 때만 표로 판정한다.
32. 번호 라벨이 여러 개이고 첫 라벨이 문서 시작점에 있거나 H1 없는 앞부분에 고신뢰 GPT 분할 안내가 있으면 첫 라벨 앞 내용을 묶음 안내로 보고 글 본문에 붙이지 않는다. 그 외 선행 본문은 단일 글로 보존한다. 제목 표식이 없는 다음 줄은 그 뒤에 질문이 이어질 때만 추론 제목으로 제거해 제목 없는 질문형 글의 첫 문장을 보존한다.
33. 단일 번호 라벨은 무조건 앞 내용을 자르지 않는다. 라벨이 첫 줄이거나 펜스·링크·줄 사이 상태와 백틱 길이를 맞춘 인라인 코드를 제외한 앞부분 한 줄에 모바일·블로그 원고 도메인, 복사 동작, 글별 묶음, 준비 완료 신호가 함께 있고, 뒤에서 인라인·명시 제목·질문·독립 제목 뒤 질문이 확인될 때만 글 시작점으로 사용한다. 일반 파일 복사 글과 코드 속 안내문 예시는 근거로 쓰지 않는다.
34. 발행본 HTML은 DOM에 렌더링하거나 실행하지 않고 최대 500,000자 안에서 태그 수와 인라인 style 값만 읽는다. `pt` 글자 크기는 `px`로 환산하고 RGB·HEX 색상은 같은 표현으로 정규화한다.
35. 전체 교체 붙여넣기일 때만 HTML이 본문 전체와 대응한다고 판단한다. 부분 붙여넣기나 붙여넣기 뒤 직접 수정은 HTML을 폐기해 오래된 서식 정보로 잘못 비교하지 않는다.
36. 텍스트 내용 점수와 서식 점수를 분리하고, HTML이 없는 경우에는 텍스트 결과를 유지하면서 `서식 미확인`으로 표시한다.
37. 본문 내용이 같을 때는 태그 개수뿐 아니라 각 텍스트 토큰에 실제로 적용된 글자 크기·강조·링크·색상 등을 결합해 서식이 다른 문구로 이동한 경우를 검출하고, 네이버가 동일 서식을 여러 wrapper로 분할한 경우는 일치 처리한다. 본문 자체가 다르면 위치 결합을 끄고 서식 값과 구조를 독립 비교해 내용 차이가 서식 점수를 오염시키지 않게 한다.
38. 발행본에 제목이 함께 복사된 경우 텍스트와 HTML 모두에서 선두 제목 블록을 제외하며, 비정상 닫는 태그는 스택 최상단만 확인해 공격성 HTML도 선형 시간으로 처리한다.
39. 서식 위치 fingerprint는 공백 제외 문자 수와 연속된 서식 run만 스트리밍 해시해 띄어쓰기 차이를 무시하고 wrapper 분할을 정규화한다. 가시 텍스트 120,000자를 넘는 비정상 HTML은 서식 확인 불가로 조기 중단한다.
40. 좌우 작업 영역은 동일한 데스크톱 높이 상수를 사용하고 내부 flex 자식에 `min-height: 0`을 적용해 페이지 전체 대신 입력창과 결과 목록만 스크롤되게 한다. 확장 상태는 별도 뷰 모델로 계산해 모바일 고정 높이와 데이터 손실을 피한다.
41. 주제명·번호형 제목은 코드 블록 밖에서만 수집하고 주제명을 공백·강조 문자 기준으로 정규화한다. 반복 H1이 있으면 기존 H1 경계를 먼저 적용하고, 그 외에는 주제별 첫 번호·후속 다른 번호 여부만 고정 크기로 집계해 선형 시간에 경계를 판정한다.
42. 구분선은 최상위 묶음 경계를 유지하되 각 구분선 구간을 번호 라벨·반복 H1·주제명 번호 순서로 한 번 더 분리한다. 따라서 서로 다른 분리 신호가 한 글뭉치에 섞여도 먼저 찾은 한 종류에서 처리를 끝내지 않는다.
43. macOS 앱 번들은 서버 생명주기를 직접 소유하지 않는다. 제출된 launchctl 작업이 `npm run dev`를 실행하고 stdout·stderr를 사용자 전용 0700 로그 디렉터리의 0600 파일에 기록해 런처 종료가 서버에 종료 신호를 전달하지 않게 한다. 실행기 전체를 macOS `lockf`의 BSD 커널 잠금 안에서 직렬화하므로 PID 파일을 직접 회수하지 않으며, 프로세스가 종료되면 잠금은 커널이 자동 해제한다.
44. 반응 유도 문구는 외부 AI나 사용자 문자열 보간 없이 검증된 고정 문구만 선택한다. 코드·이미지 프롬프트는 분류와 중복 탐지에서 제외하고, 기존 문구의 순서를 거슬러 질문을 뒤늦게 추가하지 않으며 안전하게 뒤따를 수 있는 댓글·공감 문구만 보충한다.
45. 기존 고정 마무리 문장을 제거한 다음 종단 구분선을 정리하고 마지막 해시태그 전용 줄을 분리한다. 일반 글은 `본문 → 해시태그 → 구분선 → 마무리`, 에버랜드 글은 `본문 → 놀이기구 링크 → 해시태그 → 구분선 → 마무리`로 직렬화해 고정 마무리가 글의 마지막에 남는다.
46. 번호 라벨의 구분 문자 분기는 `—`, `–`, `―`, `-`를 명시적으로 소비한다. 번호 라벨 핵심 패턴은 `N번 글`에서 끝나므로 `N번 글쓰기` 같은 접두어 유사 문장은 경계로 오인하지 않는다. 반복 라벨 앞에 H1이 없고 GPT 분할 안내 신호가 있을 때만 메타 문구로 버리며, 그렇지 않으면 전체를 단일 글로 보존한다. 단일 글 안의 후속 라벨은 전체 글 제목보다 우선하지 않는다. 경계 수집은 정제 후 새로 노출된 위치가 아닌 원문 줄 시작만 검사하며, 펜스·여러 줄 인라인 코드 속 라벨·구분선을 제외하고 이스케이프된 백틱은 코드 시작으로 보지 않는다.
47. 로컬 데이터는 `~/Library/Application Support/바로발행/database` 아래의 D1/SQLite 상태로 보존한다. 실행 전 Drizzle migration을 같은 영속 경로에 적용하고 실패하면 서버 시작을 중단한다.
48. 브라우저는 최초 연결 시 기존 localStorage 세 컬렉션을 검증·정규화한 스냅샷으로 만든다. 마이그레이션 ID와 payload hash를 먼저 로컬에 기록해 재시도해도 동일 요청이 되며, 성공해도 원본 자료는 즉시 삭제하지 않는다.
49. DB repository는 스냅샷 읽기와 revision을 같은 D1 batch에서 가져오고, 예상 revision 판정·컬렉션 전체 교체·revision 증가도 하나의 원자적 batch로 처리한다. API service의 mutation queue와 함께 여러 탭과 여러 서버 인스턴스의 갱신 유실을 막고, 충돌은 409로 반환해 클라이언트가 최신 상태를 읽은 뒤 제한 횟수 안에서 다시 계산한다.
50. 앱 데이터 API는 `localhost`, `127.0.0.1`, `[::1]` host만 허용한다. 모든 요청은 사용자 전용 0400 접근 토큰을 요구하고, 쓰기는 정확히 같은 Origin과 JSON Content-Type을 추가로 요구한다. 본문은 12MB까지만 스트리밍으로 읽고 초과 시 조기 취소하며 스키마 검증과 일반화된 오류 응답을 적용한다.
51. 런처는 접근 토큰을 query나 프로세스 인자가 아니라 URL fragment가 든 0400 `.webloc`으로 브라우저에 전달한다. 브라우저는 토큰을 같은 origin localStorage에 보관한 즉시 fragment를 주소에서 제거한다.
52. `npm run dev`와 `npm run start`는 동일한 사용자 전용 DB 경로에 migration을 먼저 적용한다. 기존 DB가 컬렉션 한도까지 찬 경우 localStorage 병합은 기존 DB 행을 밀어내지 않고 초과된 이전 자료를 건너뛴다.
53. 서버가 새로 시작될 때 256비트 접근 토큰을 원자적으로 교체해 이전 브라우저 토큰을 무효화한다. 토큰은 migration·Wrangler의 프로세스 환경에 넣지 않고 Vite config의 0400 파일 읽기 또는 Wrangler의 0400 `--env-file`로만 Worker에 주입한다. 직접 실행 TTY에는 새 fragment bootstrap 주소를 표시한다.
54. 직접 실행은 사용자 전용 0600 `server.lock`을 `lockf`로 잡은 프로세스 안에서만 진행한다. 이 잠금은 서버 수명 전체에 유지되며 고정 loopback 포트 확인과 토큰 회전을 모두 감싸므로, 이미 실행 중이거나 동시에 시작된 두 번째 프로세스는 새 토큰을 만들기 전에 중단된다. 최소 부트스트랩 `locked-runner.mjs`가 실제 서버 모듈을 불러오기 전에 무작위 이름의 0600 PID handshake 파일을 원자적으로 기록한다. 외부 실행기는 임의 timeout 없이 PID 등록 또는 잠금 프로세스 종료를 기다린 뒤 실제 서버 PID에 종료 신호를 전달해 서버가 끝날 때까지 `lockf`와 잠금이 살아 있게 한다.
55. 글뭉치·바로가기·히스토리 mutation의 성공뿐 아니라 실패도 요청 세대를 확인한다. 오래된 실패는 경고와 토스트를 띄우지 않고 최신 DB 재조회만 예약해 이후 성공 상태를 덮지 않는다.
