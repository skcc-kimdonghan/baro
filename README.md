# 바로발행

GPT에서 작성한 여러 개의 원고를 한 번에 붙여넣으면 글별로 나누고, 네이버 블로그에 바로 붙여넣기 좋은 형태로 정리해 주는 개인용 로컬 웹 도구입니다.

- 서비스명: **바로발행**
- GitHub 저장소명: **`naver-blog-finalizer`**
- 기본 실행 주소: **`http://localhost:45173`**
- 로그인, 외부 데이터베이스 계정, API 키: **필요 없음**

## 주요 기능

- 3~5개 이상의 원고를 한 번에 붙여넣고 글별 자동 분리
- `글 N`, `N번 글`, `### N번 글 — 제목`, `N편`, `## 에버랜드 1번`·`## 에버랜드 2번`, `---`, 반복 제목을 글 구분 기준으로 인식
- 글 구분용 번호, 앞부분 안내문, GPT 작성 메모와 참고 표시 자동 제거
- 제목은 별도로 분리하고 복사 본문에서는 제외
- 제목 다음 첫 질문을 16px 기울임꼴로 변환
- 일반 `A:`와 `**A: 핵심 답변**` 아래에는 네이버 붙여넣기에서도 유지되는 빈 줄을 정확히 한 칸만 적용
- `1)`·`2)` 계산 단계와 계산식을 독립 문단으로 정리하고 결과 설명 전에는 빈 줄을 정확히 한 칸만 적용
- 문단, 목록, 인용문, 링크, 코드와 Markdown 표를 네이버용 서식으로 변환
- 정렬 구분행이 빠진 연속 `항목 | 내용 | 조치` 형식과 `\|`로 시작하는 깨진 Markdown 표를 실제 표로 복구
- 표 제목행 배경색과 셀 정렬 자동 적용
- 문자로 입력된 잘못된 구분선을 표준 구분선으로 교체
- 이미지 생성 요청을 본문에서 분리해 별도 블록으로 제공
- 모든 글 끝에 지정된 질문·댓글·공감 마무리 문구를 동일하게 자동 추가
- 이미 들어간 동일한 고정 문장은 제거한 뒤 굵은 질문 → 댓글 → 공감 순서로 한 번만 표준화
- 글 마지막은 `해시태그 → 구분선 → 굵은 질문 → 댓글 → 공감` 순서로 통일
- 제목 또는 본문에 `에버랜드`가 명확히 있는 글에만 우리아이 놀이기구 찾기 링크 자동 추가
- 글별 제목 복사, 안전 복사, 본문 서식 복사
- 발행 완료 체크 후 실제 발행 글의 내용과 클립보드 HTML 서식 비교
- 내용 점수와 서식 점수를 분리해 누락, 추가, 순서, 문단과 필수 링크 차이 표시
- 글자 크기, 글꼴, 줄 간격, 자간, 굵게, 기울임, 밑줄, 목록, 표, 구분선, 링크, 정렬, 색상, 여백과 테두리 차이 표시
- 카드에는 비교 상태만 간단히 표시하고 입력·상세 결과는 별도 창에서 확인
- 데스크톱 입력·결과 영역 높이를 맞추고, 긴 원문은 입력창 내부 스크롤과 `입력창 펼치기/접기`로 관리
- 저장한 글뭉치·발행 완료 히스토리·상단 바로가기를 이 Mac의 로컬 DB에 보관
- 자주 가는 ChatGPT 채팅이나 일반 웹사이트를 이름과 HTTPS URL로 최대 6개까지 상단 바로가기에 등록하고 새 탭으로 열기

## 빠른 시작

### 1. 준비 사항

- [Node.js](https://nodejs.org/) 22.13.0 이상
- npm

별도의 회원가입, ChatGPT 로그인, 데이터베이스 설치나 환경변수 설정은 필요하지 않습니다. 앱을 처음 실행하면 내장된 SQLite 호환 로컬 DB가 자동으로 준비됩니다.

### 2. 설치 및 실행

```bash
git clone https://github.com/<GitHub-아이디>/naver-blog-finalizer.git
cd naver-blog-finalizer
npm ci
npm run dev
```

터미널에 표시되는 `보안 시작 주소`를 한 번 클릭해 여세요. 주소의 `#baro-token=...` 부분은 서버로 전송되지 않으며 앱이 인증 정보를 저장한 직후 주소창에서 자동으로 사라집니다. 이후에는 [http://localhost:45173](http://localhost:45173)을 바로 열 수 있습니다.

이미 서버가 실행 중이거나 동시에 다른 실행이 시작됐을 때 `npm run dev` 또는 `npm run start`를 다시 호출하면 사용자 전용 프로세스 잠금이 기존 서버와 접근 토큰을 보호하며 두 번째 실행을 중단합니다. 이때는 새로 실행하지 말고 기존 주소나 바탕화면 `바로발행.app`을 여세요.

### 바탕화면 바로가기

macOS 바탕화면의 `바로발행.app`은 저장소의 [`scripts/desktop-launcher.zsh`](scripts/desktop-launcher.zsh)를 실행 파일로 사용합니다. 다른 Vite 앱과 충돌하지 않도록 [`scripts/server-port`](scripts/server-port)에 지정된 전용 포트 `45173`을 사용합니다. 바로가기는 개발 서버를 `launchctl` 작업으로 분리해 시작하므로 앱 실행 프로세스가 끝나도 `http://localhost:45173` 서버가 유지됩니다.

사용자 LaunchAgent `com.local.naver-blog-finalizer.autostart`가 설치된 Mac에서는 로그인할 때 브라우저를 띄우지 않고 서버만 미리 시작합니다. 바로가기를 누르면 이미 준비된 서버를 즉시 엽니다. 실행 판정은 리스너의 사용자·작업 경로, 전용 정적 상태 파일, 실제 첫 화면의 HTTP 성공을 함께 확인합니다. 런처 오류는 `~/Library/Logs/바로발행/launcher.log`, 서버 출력은 `~/Library/Logs/바로발행/server.log`에서 확인할 수 있습니다.

현재 Mac에서 바로가기와 로그인 자동 실행을 다시 설치하려면 다음 명령을 실행합니다. 설치기는 ChatGPT 앱에 포함된 Node.js를 사용자 전용 보호 폴더의 임시 파일로 먼저 복사한 뒤 그 동일 파일의 Apple·OpenAI 서명 체인과 시스템 라이브러리 의존성을 검증합니다. 복사본에는 로컬 개발 서버의 네이티브 모듈만 로드할 수 있는 최소 실행 권한을 적용하고 콘텐츠 해시 이름과 원자적으로 교체되는 매니페스트를 사용하므로 Homebrew 경로나 PATH 변경, 동시 설치나 중간 종료에 영향을 받지 않습니다.

```bash
zsh scripts/install-macos-autostart.zsh
```

## 사용 방법

1. 자주 쓰는 GPT 채팅이나 웹사이트가 있다면 상단 `추가`에서 이름과 `https://...` 주소를 등록합니다. 등록한 버튼은 새 탭으로 열리고 삭제할 때까지 이 Mac의 사용자 전용 로컬 DB에 저장됩니다.
2. GPT에서 작성한 전체 글뭉치를 복사합니다.
3. 바로발행의 입력창에 그대로 붙여넣습니다.
   긴 글은 입력창 안에서 스크롤하거나 `입력창 펼치기`로 편집 영역을 늘릴 수 있습니다.
4. 자동 정리가 실행되지 않았다면 `글별로 정리하기`를 누릅니다.
5. 분리된 각 글에서 제목과 본문을 확인합니다.
6. `제목 복사`와 `본문 서식 복사`를 눌러 네이버 블로그 SmartEditor에 붙여넣습니다.
7. 이미지 생성 요청이 분리되었다면 `아래 이미지를 생성해주세요` 블록을 따로 사용합니다.
8. 실제로 발행한 뒤 `발행 완료`를 체크하고, 네이버 발행 본문 전체를 복사해 비교 창에 붙여넣습니다.
9. 반복해서 사용할 원고 묶음은 `글뭉치 저장`으로 로컬 DB에 보관합니다.

네이버에서 복사할 때 HTML이 함께 들어오면 `HTML 서식 감지됨`이 표시됩니다. 붙여넣은 뒤 입력창에서 직접 수정하거나 일반 텍스트로만 복사한 경우에는 내용 비교는 계속되지만 서식은 `확인 불가`로 표시됩니다.

## 인식하는 글 구분 형식

아래 형식은 모두 글을 나누는 기준으로 사용할 수 있습니다.

```text
[1번글]
첫 번째 글 제목
첫 번째 글 본문

[2번 글] 두 번째 글 제목
두 번째 글 본문
```

```text
### 1번 글
첫 번째 글 제목
첫 번째 글 본문

### 2번 글
두 번째 글 제목
두 번째 글 본문
```

번호 라벨 뒤에 긴 대시(`—`, `–`, `―`)와 제목이 붙어도 같은 방식으로 분리합니다. 대시 앞뒤 공백은 없어도 됩니다.

```text
### 1번 글 — 롯데월드 부산 오후권 17,100원
첫 번째 글 본문

### 2번 글—롯데월드 부산 종일권 할인
두 번째 글 본문
```

```text
1편
첫 번째 글 제목
첫 번째 글 본문

2편
두 번째 글 제목
두 번째 글 본문
```

같은 주제명 뒤의 번호만 바뀌는 Markdown 제목도 글 경계로 인식합니다.

```text
## 에버랜드 1번
첫 번째 글 제목
첫 번째 글 본문

## 에버랜드 2번
두 번째 글 제목
두 번째 글 본문
```

```text
글 1
첫 번째 글 제목
첫 번째 글 본문

---

글 2
두 번째 글 제목
두 번째 글 본문
```

구분 표시가 없더라도 같은 수준의 큰 제목이 반복되면 별도 글로 분리합니다.

## 표 입력 예시

Markdown 표가 텍스트로 들어와도 실제 표 서식으로 변환합니다.

```text
| 순서 | 추천 체험 |
| :-: | :----------: |
| 1 | 글로벌페어 F1 머신 |
| 2 | 타이어 롤링 챌린지 |
| 3 | 레이싱카·장비 전시 |
```

역슬래시가 붙은 `\| 순서 | 추천 체험 |` 형태도 복구 대상입니다.

정렬 구분행이 없어도 열 수가 같은 행이 3개 이상이면 첫 행을 제목행으로 사용합니다. 제목행과 데이터행 사이의 빈 줄 하나는 같은 표로 이어집니다.

```text
확인할 항목 | 가입내역에서 볼 내용 | 확인 후 할 일

가입기간 | 현재 가입월수 | 120개월 충족 여부 확인
납부 공백 | 납부예외·미납 여부 | 공백의 종류 확인
예상연금 | 표시된 예상 월액 | 앞으로 납부한다는 가정 확인
```

## 복사 버튼 차이

| 버튼 | 용도 |
| --- | --- |
| 제목 복사 | 네이버 블로그 제목 입력란에 붙여넣기 |
| 본문 안전 복사 | 서식 호환성이 가장 높은 일반 텍스트 복사 |
| 본문 서식 복사 | 제목을 제외한 문단, 기울임, 구분선과 표 서식을 포함해 복사 |

네이버 SmartEditor가 외부 HTML/CSS를 자체적으로 정리하므로 색상이나 간격은 편집기 상태에 따라 일부 달라질 수 있습니다. 문제가 생기면 `본문 안전 복사`를 사용하세요. 이미지는 네이버 포토 업로더로 별도 등록해야 합니다.

## 데이터 저장과 개인정보

- 작성 중인 미저장 원고와 원본 클립보드 HTML은 탭 메모리에만 두며 DB에 저장하지 않습니다.
- `글뭉치 저장`을 누른 원고, 비교를 마친 발행 기록, 상단 바로가기만 현재 macOS 사용자 전용 로컬 DB에 저장합니다.
- DB 파일은 `~/Library/Application Support/바로발행/database` 아래에 남으므로 브라우저나 서버, 컴퓨터를 껐다 켜도 복원됩니다.
- 같은 macOS 사용자 계정에서 연 바로발행 브라우저들은 같은 목록을 봅니다. 다른 기기·다른 macOS 사용자·클라우드와는 동기화되지 않습니다.
- 같은 주소(`http://localhost:45173`)에서 저장된 기존 브라우저 `localStorage` 자료는 첫 실행 때 한 번 DB에 병합하며, 이전이 실패해도 원본 브라우저 자료를 지우지 않습니다. 브라우저 보안상 예전 `localhost:5173` 자료는 자동으로 읽을 수 없습니다.
- 브라우저 캐시나 사이트 데이터를 지워도 이미 DB로 저장된 목록은 지워지지 않습니다. 삭제는 앱의 각 목록 관리 기능에서 수행합니다.
- 로컬 데이터 API는 현재 macOS 사용자에게만 발급된 접근 토큰을 요구합니다. 토큰은 `~/Library/Application Support/바로발행/access-token`에 0400 권한으로 저장되고 주소창에서는 즉시 제거됩니다.
- 접근 토큰은 서버를 새로 시작할 때마다 교체됩니다. 재시작 뒤 DB 연결 안내가 보이면 바탕화면 `바로발행.app` 또는 터미널의 새 `보안 시작 주소`로 한 번 다시 여세요.
- 공용 Mac에서는 같은 macOS 계정을 쓰는 사람이 저장 내용을 볼 수 있으므로 사용 후 저장 목록과 히스토리를 삭제하세요.

## GitHub에 올리기

현재 Git 저장소의 기존 원격 주소를 보존하려면 GitHub 원격 주소를 `github`라는 별도 이름으로 추가하는 방식이 안전합니다.

```bash
git remote add github https://github.com/<GitHub-아이디>/naver-blog-finalizer.git
git push -u github HEAD
```

GitHub에서 비어 있는 `naver-blog-finalizer` 저장소를 먼저 만든 뒤 실행하세요. 이미 `github`라는 원격 주소가 있다면 `git remote add` 대신 기존 주소를 확인하고 사용해야 합니다.
